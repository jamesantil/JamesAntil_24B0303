# RegimeShift: Macro-Aware Tactical Asset Allocation Engine

**Summer of Quant — Advanced Capstone**

A system that (1) statistically detects the market's hidden "mood" — Bull,
Bear, or Crisis — from price/volatility data using a Hidden Markov Model,
and (2) automatically re-solves a multi-asset (equity / bonds / gold)
portfolio's optimal weights for whatever regime it's currently in, using
convex optimization (`cvxpy`). The whole thing is evaluated with a
leakage-safe walk-forward backtest, because the entire point of a regime
detector is worthless if it was allowed to peek at the future while being
built.

## 2. How to run

```bash
python -m venv .venv && source .venv/bin/activate      # optional but recommended
pip install -r requirements.txt

python main.py                        # full pipeline, real yfinance data, 2010-2025
```

or open `notebooks/Regime_Shift_Capstone.ipynb` and Run All.

Useful flags on `main.py`:

```bash
python main.py --start 2012-01-01 --end 2025-01-01     # custom date range
python main.py --rebalance_freq 21 --tc_bps 10          # monthly rebalance, 10bps cost
python main.py --demo                                   # OFFLINE synthetic data — pipeline
                                                          # smoke-test only, NOT the reported results
```

Everything in `outputs/` is regenerated by either the script or the
notebook — there's no manual step in between.

## 4. Key decisions (the "why")

### Why these three assets + VIX?
`^NSEI` (Nifty 50), `NETFLTGILT.NS` (a long-duration government-bond ETF —
deliberately *not* a cash-like liquid fund, so it's actually rate-sensitive
and behaves like a real "bond" leg), and `GOLDBEES.NS` (gold) give three
structurally different risk exposures on the NSE. `^INDIAVIX` is used only
as a regime-detection **feature** — it's the market's own forward-looking
fear gauge, deliberately excluded from the optimizable portfolio since VIX
itself isn't a directly investable spot instrument.

### Why 3 hidden states?
This is a *choice*, not something `hmmlearn` discovers on its own — and it's
the direct translation of the brief ("bull/bear/crisis"). We also tried 2
and 4 states during development: 2 states collapses Bear and Crisis into one
indistinguishable "down" regime, losing exactly the distinction the project
asks for; 4+ states starts splitting Bull into sub-states that aren't
economically meaningful and are harder to act on with a 3-way
regime-conditional optimizer. 3 is the smallest model that actually answers
the question being asked.

### Why these features (momentum, volatility, VIX)?
Price level alone is nearly useless for regime detection — the same price
can be reached after a calm grind up or a violent crash-and-recover.
**Momentum** captures direction; **volatility** (the more reliable
crisis signal in practice) captures uncertainty; **VIX level/change** adds
an independent, forward-looking signal that isn't purely a function of
realized equity returns. A rolling 63-day bond/equity correlation is also
included, since it flips sign in genuine flight-to-quality events.

### Why `covariance_type="diag"` for the HMM?
With ~6 features and as few as ~750 training observations in the first
walk-forward fold, a full covariance matrix (21 free parameters/state) is a
lot to estimate reliably. `"diag"` (6 params/state) trades some
expressiveness for materially more stable Baum-Welch fits on the smaller
early folds.

### Regime → objective mapping
| Regime | Objective | Constraints | Rationale |
|---|---|---|---|
| Bull | Max Sharpe (tangency portfolio, convex QP reformulation) | long-only, sum=1 | Calm uptrend → full risk-adjusted participation |
| Bear | Min variance | long-only, EQUITY ≤ 45% | Capital preservation over upside; the cap stops the optimizer from "min-variance-ing" into 100% equity off a temporarily-low short-window vol estimate |
| Crisis | Min variance | long-only, EQUITY ≤ 15%, GOLD ≥ 30% | Forces a real flight-to-quality tilt rather than trusting a covariance matrix estimated on a handful of chaotic days |

### Why expanding, not rolling, walk-forward windows?
Regimes recur — a well-fit Crisis emission distribution from one crash is
still useful context for the next one — and the dataset isn't long enough to
comfortably discard history. `src/walkforward.py` also ships
`rolling_walk_forward_splits` as a documented alternative (compared visually
in the notebook's robustness-check section).

### Rebalance frequency & transaction costs
Weekly (every 5 trading days) by default: frequent enough to react to a
regime flip within about a week, infrequent enough to keep turnover/costs
realistic. Costs default to 7.5 bps per unit of turnover (inside the
required 5–10 bps range); results are reported **both** gross and net of
costs specifically so the effect of costs is visible, not hidden.

### The single most important design choice: causal regime decoding
The project guide's own reference sketch calls `model.predict(test_fold)`
once per fold — this runs Viterbi *smoothing* over the entire test block at
once, meaning the regime label assigned to day 5 of a 126-day test fold
could, in principle, be influenced by what happens on day 120 of that same
fold. That's still a real (if subtle) form of lookahead bias, even though it
respects the train/test fold boundary. `regime_hmm.causal_predict_regimes`
instead decodes the **growing prefix** (all training data + all test data up
to and including the current rebalance date) at every single rebalance, and
keeps only the state assigned to the last time step — so the label at day
*t* is provably a function of data with index ≤ *t* only. The notebook's
Section 10.1 measures how much this actually changes labels vs. the faster
batch approach, as a documented robustness check.

## 5. Concepts covered

- Hidden Markov Models & Viterbi decoding (`hmmlearn`)
- Convex portfolio optimization, including the tangency-portfolio convex
  reformulation of max-Sharpe (`cvxpy`)
- Walk-forward validation (expanding + rolling variants)
- Lookahead-bias sources and fixes, at every layer: feature scaling, HMM
  fitting, regime decoding, and moment estimation
- Sharpe / Sortino / Calmar ratios, max drawdown, turnover
- Transaction-cost modelling

## 6. Limitations & honest caveats

- HMM state labels (Bull/Bear/Crisis) are assigned via a volatility/momentum
  ranking heuristic on the model's own fitted states, not ground-truth
  labels — there is no NBER-style "true" regime series to validate against,
  which is inherent to the unsupervised nature of the problem.
- Moment (`mu`, `Sigma`) estimation uses a 126-day trailing window; this is a
  standard but noisy estimator, especially for `mu`. The optimizer's
  regime-specific constraints (equity caps, gold floors) are partly there to
  bound the damage a noisy `mu` estimate can do.
- `--demo` mode uses synthetic, regime-switching data purely so the *code*
  can be smoke-tested without a network connection. It is not used to
  produce any reported result.
